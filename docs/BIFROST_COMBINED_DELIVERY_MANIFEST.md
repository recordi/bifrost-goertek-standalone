# BIFROST 联合交付说明

本仓库是 BIFROST 联合方案，不是任一方的原始工程快照。当前交付将同学提供的 UI 基线、我们完成的数据治理与自动适配链路，以及双方之间的只读兼容层放在同一套可运行工程中。

## 组成边界

| 部分 | 当前来源/责任 | 在联合方案中的作用 |
|---|---|---|
| UI 基线与页面壳 | 同学提供的 UI 基线分支（`origin/agent/ui-baseline-v3-2-1`） | 提供看板导航、角色页面、事件页和视觉基线 |
| 数据治理与自动适配 | 我们在联合分支新增的 `.omp/workstreams/autoadapt`、`.omp/workstreams/compile`、`.omp/workstreams/presentation` | 上传数据后生成档案、字段映射、质量检查、统一数据集和统一载荷 |
| 智能体编排与只读 Skill | `.omp/agents`、`.omp/integration`、`.omp/skills/bifrost-*` | 按角色拆解任务、输出结构化结论、保留证据和人工确认边界 |
| 同学能力兼容层 | `.omp/workstreams/peer_pipeline`、`.omp/integration/peer_skill_*` | 以只读后处理方式复用同学能力；不覆盖正式 KPI，不写回源数据 |
| 前端动态接入 | `output/bifrost-ui-runtime/src` | 将统一载荷接入页面，并支持“分析→确认映射→只读预览→回退” |
| 测试材料 | `test-inputs`、`fixtures` | 官方脱敏数据与团队模拟数据，用于验证多源兼容性，不代表企业生产数据 |

## 重要事实

1. 同学的 UI 与 Skill 没有被删除，也没有被伪装成我们的原生实现。
2. 我们新增的适配器会先生成数据源档案和映射草稿；未确认的映射不能直接进入正式看板。
3. 同学能力默认以候选或只读后处理方式运行。没有证据引用的结论会被阻断，SPC/Cpk 缺少原始测量点时不会计算。
4. 动态载荷只能在会话内预览；应用预览不会修改原始文件、正式载荷或数据库，页面可回退。
5. 当前仓库中的数据均为公开/脱敏/团队模拟测试材料，不含企业内部敏感数据。
