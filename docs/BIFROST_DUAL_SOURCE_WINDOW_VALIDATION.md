# 双数据源自动适配与时间窗验证

本报告验证两套数据是否共用同一套自动适配链路，不为任一数据源单独硬编码看板逻辑。

## 验证链路

`Excel → 数据源档案 → 字段映射 → 质量检查 → 统一语义记录 → 指标能力判断 → 时间窗/产线投影 → Overview/Event Payload`

全程 `source_write_performed=false`。

## 结果

| 数据源 | 真实产线 | 可用时间窗 | OEE口径 | 良率口径 | 快照数 |
|---|---:|---|---|---|---:|
| BIFROST 模拟数据包 | 3 | 全历史、最近7班次、最近30班次、改善前、改善后 | A×P×Q 复算 | 良品数/总产量复算 | 35 |
| 歌尔官方脱敏数据 | 6 | 全历史、最近7班次、最近30班次 | 来源 OEE（缺少 A/P，未复算） | 良品数/实际产量复算 | 37 |

## 关键数值

- BIFROST 模拟数据包：复算 OEE `0.5282592907919411`，复算良率 `0.9738946723641829`。
- 歌尔官方脱敏数据：来源 OEE `0.81923`，复算良率 `0.9647682996068134`。

歌尔数据没有改善前/改善后字段，因此载荷返回：

```json
{
  "before_improvement": "未同时观察到改善前与改善后阶段",
  "after_improvement": "未同时观察到改善前与改善后阶段"
}
```

这表示“当前不可提供该切片”，不是补造阶段或把全历史冒充改善对比。

## 审计约束

1. 时间窗只基于源数据真实日期/阶段字段生成。
2. 产线只基于源数据真实产线字段生成。
3. 来源 OEE 与 A×P×Q 复算 OEE 使用不同 `value_mode`，不能混淆。
4. 每个窗口携带来源文件名、SHA-256、实际记录数和日期范围。
5. 候选 Skill、SPC/Cpk 和高风险动作仍受证据门禁与人工确认约束。
